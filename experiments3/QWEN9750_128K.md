# Qwen step9750: five 128K VT inputs

Run in the repository root on the CUDA server after activating `fyc_qwen`:

```bash
conda activate fyc_qwen
bash experiments3/run_all_experiments_qwen9750_128k.sh --resume
```

`--resume` also works on the first launch. Repeat exactly the same command after
an interruption. The default output is
`experiments3/experiments3_5/qwen9750_vt128k_5samples/experiment{3,4,5}`.
Use a different `--output-root` for a separate run; reuse that exact path to resume.
Do not run two processes against the same output directory simultaneously.

Defaults: Qwen3-8B; the requested `stage3_extend_96k128k_t065_s8_yarn4_bf16_ema_step9750.pt`
under `xattn/qwen_weights/conv_qwen3_t065_64k128k_balanced_v3`; five newly generated
Qwen-template VT inputs, seed 20261008, context target 131072; YaRN factor 4,
original context 32768; Top-k ratio 0.65, stride 8; layer16/head8/last query block.
This runs experiments 3–5, not benchmark Top-p generation.

Recovery:

- Each experiment records `run_manifest.json`: parameters, data/weight hashes,
  engine source hashes and available model/tokenizer metadata hashes must match.
- Completed cases are reused without loading the model if no inference remains.
- Within incomplete cases, `checkpoint.json` atomically saves every completed
  replacement (3/4) or policy with its repeat check (5). These trials are reused.
- The baseline prefill is recomputed to rebuild KV-independent masks. Baseline
  NLL must match within `--loss-tolerance` and score maps/masks must match exactly.
  A partially computed forward pass or unfinished repeat check is recomputed;
  GPU KV caches are not persisted.
- `trials.csv`, `trials.jsonl`, `cases.csv`, `summary.json` and plots are rebuilt
  from the completed cases/trials. Logs append. Checkpoint data is the authoritative
  partial progress before the final trial exports are written.
- Old runs created before this update have no manifest and cannot be resumed
  safely. They are preserved; use a new output directory.

The existing sparse-attention memory path is reused; this update does not add
KV offloading. CPU recovery tests and launcher dry-run checks do not constitute
a completed 128K CUDA evaluation.
